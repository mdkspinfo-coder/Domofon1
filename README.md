# Domofon Map (веб-версия / PWA для iPhone и Android)

Карта с метками домофонов. Метки видны всем пользователям, а код открывается только вошедшему в аккаунт
человеку, который принял правила и находится ближе 800 м от метки. Есть жалобы на метки, отдельная страница
модерации для владельца и модераторов, документы (политика конфиденциальности, согласие на обработку
персональных данных, правила) и удаление аккаунта. Сборка не нужна: обычные файлы (HTML + JS).

## Как обновить сайт на GitHub

Загрузи **все** файлы из архива в репозиторий поверх старых (Add file → Upload files, включая папки `supabase` и `tests`).
Новые файлы этой версии: `moderation.html`, `moderation.js`, `privacy.html`, `terms.html`, `consent.html`, `legal.js`, `legal.css`.
Файл `config.js` **не перезаписывай**, если уже вписал в него адрес и ключ Supabase: перенеси из нового только блок `OPERATOR`.
После обновления закрой приложение на iPhone и открой заново (иногда два раза): иначе может показаться старая версия из кэша.

## Подключение сервера (один раз, около 20 минут)

### 1. Проект Supabase
1. Зарегистрируйся на supabase.com → **New project**. Регион лучше `Central EU (Frankfurt)`: ближе к Польше, и для политики конфиденциальности это важно.
2. **SQL Editor → New query** → вставь всё содержимое `supabase/schema.sql` → **Run**. Скрипт создаёт таблицы, правила доступа и функции.
   При каждом обновлении приложения запускай его ещё раз целиком: он безопасно обновляет схему, данные не пропадают.
3. **Project Settings → API**: скопируй **Project URL** и ключ **anon public** в `config.js` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`).
   Ключ anon публичный, его можно хранить в репозитории. **Ключ `service_role` нигде не публикуй.**
4. **Authentication → URL Configuration**: в **Site URL** впиши адрес сайта `https://<логин>.github.io/<репозиторий>/`,
   а в **Redirect URLs** добавь `https://<логин>.github.io/<репозиторий>/**` (со звёздочками: так работает и главная страница, и модерация).

### 2. Вход через Google (бесплатно)
1. console.cloud.google.com → создай проект → **APIs & Services → OAuth consent screen** (тип External, название, твоя почта).
2. **Credentials → Create credentials → OAuth client ID → Web application**. В **Authorized redirect URIs** впиши
   `https://<твой-проект>.supabase.co/auth/v1/callback` (точный адрес показан в Supabase: Authentication → Providers → Google).
3. Скопируй Client ID и Client secret в Supabase: **Authentication → Providers → Google → Enable**.

### 3. Вход через Apple (нужен платный аккаунт)
Sign in with Apple работает только при участии в **Apple Developer Program (99 $ в год)**. Инструкция Supabase:
Authentication → Providers → Apple. Пока это не настроено, кнопка в приложении серая с подписью «появится позже».
Когда настроишь, поставь в `config.js` `PROVIDERS: { google: true, apple: true }`.

## Модерация: как стать владельцем и добавить модераторов

1. Открой сайт и **войди через Google той почтой, которая будет владельцем**. Прими документы в окне согласия.
   (Пока ты ни разу не входил, аккаунта нет, и назначить владельцем нельзя.)
2. В Supabase → SQL Editor выполни одну строку (подставь свою почту):
   ```sql
   select public.grant_owner('твоя_почта@gmail.com');
   ```
   Эту функцию клиенты вызвать не могут, только ты из панели Supabase. Владелец может быть только один; повторный запуск с другой почтой передаёт роль.
3. Перезагрузи сайт: в окне «Аккаунт» появится значок «Владелец» и кнопка **«Панель модерации»**. Она открывает отдельную
   вкладку `moderation.html` (можно открыть и напрямую). Доступ определяет сервер, а не эта страница.
4. **Добавить модератора:** вкладка «Команда» → почта человека → «Добавить модератором». Он должен хотя бы раз войти в приложение.
   Там же его можно снять с роли.

Что видит каждая роль:

| | Модератор | Владелец |
|---|---|---|
| Жалобы, код метки, почта автора | да | да |
| Почта того, кто пожаловался | нет | да |
| Отклонить жалобу, удалить метку, удалить все метки автора и заблокировать его | да | да |
| Список блокировок | да | да |
| Снять блокировку | нет | да |
| Добавлять и снимать модераторов | нет | да |

Блокировка идёт **по почте**, поэтому нарушитель не обойдёт её, удалив аккаунт и зарегистрировавшись заново. Сотрудников команды заблокировать нельзя.
Все решения записываются в таблицу `mod_log` (Supabase → Table editor).

**Жалоба:** значок флажка в окне с кодом (на чужой метке). Причины: код не подходит, выдуманная метка, частная территория,
оскорбительное название, другое. Один человек подаёт одну открытую жалобу на метку, не больше 20 в сутки; жалобы не скрывают метку сами:
решение всегда за человеком.

## Документы и согласие

- `privacy.html` (политика конфиденциальности), `consent.html` (согласие на обработку персональных данных), `terms.html` (правила).
- После входа показывается окно с двумя обязательными галочками: «правила + политика, мне 16 лет» и «согласие на обработку данных».
  Пока их нет, сервер не даёт добавлять метки, открывать коды и жаловаться. Факт согласия и версия документов записываются.
- Если изменишь тексты: поставь новую дату в шапке страниц **и** в функции `policy_version()` в `supabase/schema.sql`, запусти схему ещё раз.
  Все пользователи увидят окно согласия заново.
- **Удаление аккаунта:** «Аккаунт» → «Удалить аккаунт и данные». Удаляются аккаунт, метки, коды, согласие, журнал просмотров.
  Запись о блокировке (почта) остаётся.

### Перед публичным запуском обязательно

1. В `config.js` заполни `OPERATOR` (имя или название, почта для обращений, адрес). Пока там квадратные скобки, на страницах документов виден красный баннер.
   Эти данные публичны. Если ты физическое лицо, подумай, готов ли показывать домашний адрес: можно указать адрес для корреспонденции.
2. В `terms.html` вместо `[УКАЖИТЕ С ЮРИСТОМ]` впиши применимое право и подсудность.
3. **Покажи документы юристу**, который знает право вашей страны (для ЕС и Польши это GDPR/RODO). Это шаблоны, а не юридическая консультация:
   они составлены по тому, что приложение действительно делает, но не заменяют проверки. Особенно стоит обсудить: правовые основания, срок хранения жалоб,
   передачу данных за пределы ЕЭЗ (Supabase, Google), нужен ли реестр обработки и назначение ответственного за защиту данных, и сам риск публикации кодов домофонов.
4. Проверь на тестовом аккаунте удаление аккаунта (кнопка в приложении): функция удаляет запись из `auth.users`, и стоит убедиться, что в твоём проекте Supabase это проходит.

## Как это защищено

- **Коды лежат в отдельной таблице**, к которой у телефонов нет доступа. Метки (координаты и название) читают все.
- **Код выдаёт только сервер**: функция `reveal_code` проверяет вход, блокировку, согласие, точность GPS (не хуже 100 м) и расстояние (не больше 800 м).
  Не больше 40 разных меток в час на пользователя. Присланные телефоном координаты в базу не записываются; журнал просмотров хранит только «кто, какую метку, когда» и очищается через 30 дней.
- Добавлять метки можно после входа и согласия, не больше 30 в сутки. Удалять метку может только её автор или модерация.
- Роли и все действия модерации проверяются на сервере в каждой функции: страница `moderation.html` без роли показывает только отказ.
- Текст от пользователей (названия, комментарии, почты) на странице модерации выводится как текст, не как разметка.
- Ограничение, которое нельзя убрать: сервер верит координатам, которые прислал телефон. Подмену GPS он не отличит; от массового сбора кодов защищают лимиты.

## Как пользоваться

- Кнопка с человеком (слева сверху): вход и выход, имя, роль, удаление аккаунта, документы.
- Синяя кнопка **＋** (справа снизу): добавить домофон. Над ней кнопка с прицелом возвращает камеру к тебе по GPS.
- Серая точка: далеко (нажатие покажет расстояние). Зелёная: ближе 800 м (нажатие покажет код). Точки уменьшаются при отдалении.
- В окне с кодом чужой метки: флажок «Пожаловаться».

## Проверки

```bash
node --test tests/geo.test.js    # логика радиуса 800 м и границ Польши
bash tests/sql_test.sh           # сервер на настоящем Postgres: права, радиус, лимиты, согласия, жалобы, роли, блокировки, удаление
python3 tests/ui_local_test.py   # интерфейс в Chrome, режим без сервера
python3 tests/ui_remote_test.py  # интерфейс в Chrome, режим с сервером: вход, согласие, жалобы, роли, два пользователя
python3 tests/ui_moderation_test.py  # страница модерации: доступ, действия, команда, блокировки
python3 tests/ui_legal_test.py   # документы: подстановка данных оператора, баннер, соответствие тексту схемы
```

Тесты интерфейса подменяют GPS, карту и сервер заглушками. `sql_test.sh` гоняет настоящий Postgres, но не настоящий Supabase.
Не проверено автоматически: реальная карта и 3D, настоящий вход через Google/Apple, работа на iPhone, юридическая точность документов.

## Что пока не сделано

- Платная подписка (в окне аккаунта есть место под тариф, сама оплата не подключена).
- Уведомление модераторов о новых жалобах (сейчас нужно заходить на `moderation.html`).
- Документы только на русском; для пользователей в Польше нужна польская версия.
- GPS в вебе работает, только пока страница открыта на экране.
- Бесплатные тайлы OpenFreeMap подходят для старта; для большой аудитории нужен свой сервер тайлов или платный провайдер.
